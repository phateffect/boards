# ESP32-S3-AI-Board 录入与全库物理引脚排布补齐设计

日期：2026-07-27

## 目标

新增 ESP32-S3-AI-Board 开发板页面与可编译的综合自检示例，同时审查仓库现有全部开发板和模组页面，补齐可由资料支持的物理引脚排布。

本次工作的首要可访问性要求是：**物理排布必须以纯文本 ASCII 图或 Markdown 连接器表表达，图片只能作为来源佐证，不能成为理解引脚排布的必要条件。** 这样不依赖多模态能力的模型与纯文本工具也能完整读取硬件连接关系。

## 范围

### 新增开发板

- 新建 `boards/esp32-s3-ai-board/README.md`。
- 主来源为 <https://arduino.me/a/3274>。
- 记录 ESP32-S3-WROOM-1-N16R8、1.9" 170×320 ST7789、WS2812、数字麦克风、音频解码/功放、按键、电池、I2C、UART 与引出 GPIO。
- 保存必要的页面快照、板卡图、引脚图和原理图到 `raw/`。
- 对产品页没有给出、且无法从原理图或清晰实物图确认的信息标记 `TODO: 待核实`，不得猜测。

### 新增综合自检示例

- 新建独立 PlatformIO 工程。
- 示例采用分阶段自检：
  1. 串口输出启动信息与当前阶段。
  2. 点亮/切换 WS2812。
  3. 读取 BOOT、VOL+、VOL- 按键。
  4. 初始化 ST7789 并显示纯色或测试图。
  5. 初始化数字麦克风并输出简单电平值。
  6. 初始化音频输出并播放短测试音。
- GPIO 按产品页已给出的占用表配置。
- 若资料未说明 LCD 面板偏移、WS2812 GPIO、音频器件型号或使能逻辑，则对应阶段必须保持可单独关闭，并在页面与源码中标明待核实；不得用常见默认值冒充板级事实。

### 全库物理排布审查

覆盖实施时仓库内全部真实硬件页面：

- `boards/*/README.md`，排除 `_TEMPLATE`
- `modules/*/README.md`，排除 `_TEMPLATE`

每个页面至少检查：

1. 板载器件占用 GPIO 是否与来源一致。
2. 对外引出脚位表是否区分丝印、真实网络与功能。
3. 是否存在可由纯文本理解的物理排布。
4. 排布是否注明观察方向、接口朝向或 Pin 1。
5. 图片中的脚位信息是否已转录为 ASCII 图或 Markdown 表。
6. 原理图、引脚图与文字页面之间是否存在冲突。

## 物理排布表达规范

### 排针、邮票孔与成对焊盘

使用等宽 ASCII 图，左右两列必须保持物理相对位置，例如：

```text
视角：元件面朝上、USB-C 朝下

        ┌──────────────┐
 3V3  1 │              │ 2  GND
 IO1  3 │              │ 4  IO2
        │    USB-C     │
        └──────┬───────┘
               ▼
```

必须说明编号方向；来源没有编号时用“自上而下”等位置描述，不自行创造 Pin 编号。

### Grove、JST、FPC、MX1.25 等连接器

使用 Markdown 表或单行 ASCII，并注明插座观察面：

```text
视角：从板上插座开口向内看
Pin 1 ─ VCC | Pin 2 ─ GND | Pin 3 ─ SDA | Pin 4 ─ SCL
```

### 图片

- 原始引脚图或实物图存放于 `raw/assets/`。
- 页面可以嵌入图片，但图片旁必须有等价的纯文本转录。
- 图片看不清的脚位不得靠视觉猜测，标记 `TODO: 待核实`。

## 数据来源与冲突处理

来源优先级：

1. 官方原理图、规格书和 PCB PinMap。
2. 厂商官方产品页。
3. 清晰的板卡实物图。
4. 社区文章与示例代码。

多个来源冲突时，在页面中并列记录冲突及来源，不静默选择。可以由原理图明确裁决时，以原理图为准并说明订正。
